# Purpose

Owns the private packages of the module `tokencrypt`.

# Ownership

- `clock`: `Clock` interface (`Wall()`, `Mono()`), `Real` and the test double `Fake` (`SetWall`, `AdvanceWall`, `AdvanceMono`). Code that needs time takes a `clock.Clock` so tests can move wall and monotonic time separately.
- `crypto`: Argon2id `DeriveKEK` with `Params`/`DefaultParams`, XChaCha20-Poly1305 `Seal`/`Open` (blob is nonce then ciphertext; failures return `ErrAuth`), `AAD` encoding (version, kind, name, key ID, length-prefixed), `HKDF`, `MAC`/`VerifyMAC`, random `NewKey`/`NewID`/`NewSalt`, `Zero`. Callers zero keys they own.
- `vault`: vault directory (`header.json`, `secrets/<name>.json`, `meta.json`, `notifier.json`): `Init`, `Open`/`OpenWithClock`, `Unlock` to a `Session` (`Create`, `UpdateValue`, `Rename`, `Delete`, `Reveal`, `DeriveKey`, `ChangePassphrase`, `SetNotifier`, `LoadNotifier`, `Close` zeroes MK), `ValidName`, `MaxValueBytes`, `Vault.Exists`/`KeyID`. Header KDF parameters are bound-checked before Argon2 runs: time 1 to 100, memory 64 KiB to 1 GiB, threads 1 to 16 (`ErrBadParams`). AAD kinds `mk`, `dk`, `secret`, `notifier`, each with a key ID; the notifier AAD carries the chat ID in the name slot and the master key's key ID, so an edited chat ID or a file from another vault fails `LoadNotifier` with `ErrCorrupt`.
  - Metadata: `Vault.List`/`Get` return `Meta` (name, description, optional `ExpiresOn`, created, updated, last granted, `Flag`, current key ID, `Corrupt`) with no key and no value; `List` returns an unreadable secret file as `Meta{Name, Corrupt: true}` alongside healthy entries; `Get` still fails for that file. Corrupt `meta.json` fails the whole list; `SetDescription`, `SetExpiry`, `SetFlag` (kinds `leaked`, `invalid`; else `ErrBadFlag`), `ClearFlag` and `TouchGranted` need no key. `meta.json` holds one record per secret name and counts only for names that have a secret file: a secret file without a record lists with zero times and no flag; a record without a secret file is ignored and replaced by the next `Create`. `Create` stamps created and updated from the vault clock and stores the description; `UpdateValue` stamps updated and clears the flag; `Rename` moves the record unchanged (flag included); `Delete` drops it.
  - Token expiry: `expires_on` is an optional civil date `YYYY-MM-DD` (years 0001–9999); missing or blank means Never. `ValidExpiry`, `SetExpiry` and `Session.CreateWithExpiry` reject invalid dates before writes. `Create` defaults to Never; value updates and renames preserve the date. Expiry is informational and changes no ciphertext, flags, timestamps or grants.
  - Multi-file ordering: each mutation reads `meta.json` before changing anything, so a corrupt file fails the call with `ErrCorrupt` and no change (`Delete` reads it after the unlink). `Create` and `Rename` write the new record before the new secret file; `UpdateValue` writes the secret file, then the record; `Delete` unlinks the file, then drops the record. A crash between two writes leaves an unbacked record (ignored) or a flag that stays set, never a cleared flag on an old value. A metadata write that fails after the secret change was applied returns an error wrapping `ErrMetadata`; the secret change stands. Repair: `UpdateValue` again; `Delete` again (it prunes the record and returns `ErrNotFound`); after a failed `Rename`, `Delete` the old name. A pruning failure is returned as is.
  - File limits: header and secret JSON 2 MiB each (including the base64 encoding of a 1 MiB value); metadata 8 MiB; notifier 64 KiB. Reads check the file size and limit the stream; oversized encrypted vault files return `ErrCorrupt`, independent notifier files return generic `ErrNotifierUnavailable`. JSON writes refuse oversized output with `ErrFileTooLarge` before touching the target. `Create` treats only `os.ErrNotExist` as absence and propagates other stat errors.
  - Locking and writes: all writes go through one atomic helper (temp file, fsync, rename, directory fsync via `syncDir`; test hooks `beforeRename` and `syncDir`); `Delete` and `Rename` also sync the secrets directory after the unlink. Init, every mutating Session method and the metadata setters take a mutex keyed by the canonical vault path (symlinks resolved), shared by all `Open` and `Unlock` objects in the process, so check-then-write sequences are serialized across sessions; lock order is the session mutex, then the directory mutex; internal helpers run under the caller's lock and never re-lock; reads take no directory lock.

  - Service notifier: `service/notifier.json` holds the independent bot token and chat ID outside vault encryption. `LoadServiceNotifier` needs no key and returns caller-owned token bytes; `SetServiceNotifier` uses the vault write mutex, bounded JSON and atomic durable writes. Directory mode is `0700`, file mode `0600`; reads reject symlinks, nonregular files, wider modes and JSON over 64 KiB. Token limit is 4096 bytes; the chat ID is an optional `-` followed by ASCII digits, at most 64 bytes, and writes trim surrounding whitespace first; missing files return `ErrNoNotifier`, unsafe/unreadable files return generic `ErrNotifierUnavailable`. `ValidNotifierCredentials` applies the same token and chat ID rules to credentials from any source. `MigrateServiceNotifier` writes authenticated decrypted settings only when this file is absent; configured or corrupt service settings take precedence.

- `audit`: JSON-lines audit log. `Open(path, clk)` creates the directory and file if missing, sets modes `0700` and `0600` on existing ones, and appends to existing records (a last line without a newline gets one before the next event); `Write(Event)` refuses encoded lines over 2 MiB with `ErrTooLarge`, marshals one line (JSON escapes newlines in `Detail`), sets a zero `Time` from the clock and syncs (a sync error may leave the line in the file, so callers do not write it again); `Tail(n)` reads the newest 2 MiB plus one boundary byte, drops a partial starting line, and returns up to n valid events oldest first; `Close`. Event type constants cover secret, flag, request, grant, login, notifier and daemon events. Callers pass names, actors and reason text, never values or passphrases.

- `grants`: live grants. `New(clk, dir, chk)` returns a locked `Manager` (`Checker` supplies `Flagged` and `KeyID`; it must not call the Manager). `Add` copies the value and key ID, refuses a flagged secret, a key ID that is not current, a grant that has ended (`ErrExpired`) or one over 90 days (`ErrTooLong`), and works while locked. `Read` returns copies of the value and grant of the live grant that ends last: `ErrLocked` when none and the restore step is pending, else `ErrNoGrant`. `Revoke`, `RevokeSecret` (returns the live grants ended; also removes unrestored records), `List`, `SetLocked`, `Close` (stops the timer, zeroes values, keeps `grants.json`).
  - Expiry: wall clock for every grant; grants of 24 hours or less, and restored grants with that much time left, also expire on `Clock.Mono()`, earliest wins. A timer owned by the Manager, never waiting over one minute (`recheck`), and every `Read`/`List`/`Add` remove ended grants under the Manager lock and zero their buffers.
  - Persistence: grants over 1 hour get a record in `grants.json` (id, secret, key ID, expiry, granted-by, request ID, MAC under the 32-byte key passed to `Add`, signing the expiry as seconds and nanoseconds; no value). The Manager keeps no MAC key. It copies the secret value only after validation and persistence succeed. Grant JSON reads and writes have an 8 MiB cap; oversized reads and writes return `ErrCorrupt`, and an oversized write leaves the target intact. Every write re-reads the file and changes only its own records, so unrestored records survive; expired records are dropped on write; a failed removal is retried on the next write and hidden from `Candidates`. A corrupt file fails `Add` and `Candidates` with `ErrCorrupt` and is not overwritten.
  - Restart: `Candidates(macKey)` (key required each call, `ErrNoKey` otherwise) lists records that verify, are unexpired and at most 90 days away, not live, unflagged and on the current key ID, returns each ID once, keeps that set and does not change the file. Any candidate verification failure clears the previous candidate set. `Restore(ids, reveal)` accepts only that set, copies and zeroes what `reveal` returns, re-checks the 90-day bound, flag and key ID, then clears the locked state; unconfirmed and failed candidates leave `grants.json`.

- `core`: the service behind the web UI and the agent socket. `New(v, g, a, clk, cfg)` takes ownership of the grants `Manager` (built with `NewChecker(v)`, which reports a secret as flagged when its metadata cannot be read) and the audit log; `Close` zeroes live grants, ends waits, closes `Events()` and the log. `DefaultConfig`: 10 pending requests, 10 minute request TTL, 90 day maximum and 10 minute default grant, 5 failures then a 5 minute lockout; a zero `Config` field takes that value.
  - Passphrase operations (`Create`, `UpdateValue`, `Rename`, `Delete`, `Grant`, `ClearFlag`, `SetNotifier`, `Unlock`, `RestoreGrants`, `Verify`): one shared throttle; a lockout ends when either clock passes it; throttled attempts are refused before any key derivation and are not audited; a wrong passphrase writes `login.failed`; a success resets the count. Key derivations run one at a time. The vault session and master key exist only inside the call; the passphrase is not kept or zeroed (the caller owns it).
  - Agent operations: `Read`, `Request`, `Wait`, `Flag`, `Status`. `Flag` needs no passphrase. Values and durations are validated before the throttle is touched.
  - Ordering: every operation holds one lock, so once `Flag`, `Revoke`, `UpdateValue`, `Rename` or `Delete` returns, no later `Read` returns the old value. Live grants are revoked before the vault mutation, whatever its result. A flag revokes grants before it is stored and denies the secret's pending requests. Descriptions on `Create` and `SetDescription` have a 1 KiB UTF-8 byte limit; control, format and line-separator characters become spaces. A secret whose metadata cannot be read refuses `Read`, `Request` and `Grant`; `Status` includes named `Corrupt` entries for unreadable secret files; a whole-list error sets a generic `Status.Error` and leaves `Secrets` empty.
  - Token expiry: `CreateWithExpiry` validates the optional date before authentication and stores it with creation. `SetExpiry` follows the authenticated description metadata policy, takes the operation lock and preserves grant/read behavior; the socket exposes expiry only through `Status`.
  - Requests: expire 10 minutes after creation on wall time or monotonic time, whichever comes first; checked on every call and by `Wait` (rechecks each second). Ended requests stay visible to `Wait` (last 100). Reasons and actors are cut to 200 and 64 characters; control, format and line-separator characters become spaces.
  - Audit: flag events carry `Detail` JSON `{"kind","actor","reason"}`; other events carry JSON objects of IDs and names, never values or passphrases. A failed write is reported as `ErrAudit` after the action stands, never retried; a grant whose `grant.started` cannot be written is revoked. `grant.ended` and `request.expired` are written when a later call notices them. `LogNotifierEvent` accepts only types starting `notifier.`.
  - Events: `Events()` is buffered (64) and drops when full; kinds `request.created` and `flag.set`, carrying actor, flag kind, reason and duration for the notice.
  - Notifier: `SetNotifier` authenticates with the shared passphrase throttle, writes only independent service settings and audits without token or chat ID. `Notifier` supplies caller-owned credentials to daemon/web code without unlocking or restoring grants; the socket exposes no credential route. `Unlock` reads service settings first and migrates encrypted `notifier.json` only after successful authentication when service settings are absent; failures expose generic `NotifierErr`.
  - Restart: `Unlock` returns the notifier credentials and saved-grant candidates; with none it ends the locked state. Corrupt grant storage produces a generic `GrantsErr` warning, loads the notifier and ends both locked states without restoring values; the corrupt file stays intact and long grants fail closed. `RestoreGrants` derives the key again, rebuilds the candidate set and restores only the confirmed IDs. Corrupt grant storage ends both locked states, restores nothing and returns a generic error wrapping `grants.ErrCorrupt`.

- `api`: private Unix-socket HTTP API with same-uid admission; see `api/AGENTS.md`.
- `cli`: agent command runner and child environment; see `cli/AGENTS.md`.
- `daemon`: exclusive vault ownership, first-run setup, shared service and listener shutdown; see `daemon/AGENTS.md`.
- `notify`: daemon-lifetime notification budget and bounded Telegram transport; see `notify/AGENTS.md`.
- `web`: embedded authenticated website, setup and user management forms; see `web/AGENTS.md`.
- `securemem`: best-effort buffer locking and release for keys and live grant values.

# Local Contracts

- Packages under `internal/` are not importable outside the module.
- Tests use temporary directories and fake secret values only.

# Work Guidance

- Write the failing test first, then the implementation.

# Verification

- `toolchain/check` runs `go test -race ./...`, including `internal/audit`, `internal/clock`, `internal/core`, `internal/crypto`, `internal/grants` and `internal/vault`.
- `toolchain/run go test -bench DeriveKEK -run '^$' ./internal/crypto/` times `DefaultParams`; re-tune `DefaultParams` when the target is about one second per derivation.
